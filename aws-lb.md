# AWS Load Balancer Interview Questions and Answers

This document contains common interview questions related to AWS Elastic Load Balancing (ELB), covering ALB, NLB, and GWLB.

## 🔹 Basic Level

### 1. What is AWS Load Balancer?
**Answer:**
**AWS Load Balancer** is a service that automatically distributes incoming application traffic across multiple targets such as EC2 instances, containers, and IP addresses to improve availability and fault tolerance. It is part of Amazon Web Services.

### 2. What are the types of Load Balancers in AWS?
**Answer:**
AWS provides load balancing through **Elastic Load Balancing (ELB)**, which includes:
*   **Application Load Balancer (ALB):** Layer 7 (HTTP/HTTPS).
*   **Network Load Balancer (NLB):** Layer 4 (TCP/UDP/TLS).
*   **Gateway Load Balancer (GWLB):** For third-party virtual appliances (Layer 3 Gateway + Layer 4 LB).
*   **Classic Load Balancer (CLB):** Legacy (Layer 4 & 7).

### 3. What is the difference between ALB and NLB?
**Answer:**

| Feature | Application Load Balancer (ALB) | Network Load Balancer (NLB) |
| :--- | :--- | :--- |
| **OSI Layer** | Layer 7 (Application) | Layer 4 (Transport) |
| **Routing** | Path-based, Host-based, Query-string | IP + Port based |
| **Protocols** | HTTP, HTTPS, WebSocket, gRPC | TCP, UDP, TLS |
| **Performance** | Good for web apps | Ultra-high performance, low latency |
| **Static IP** | No (DNS name only) | Yes (Static IP / Elastic IP) |

### 4. What is a Target Group?
**Answer:**
A **Target Group** routes requests to one or more registered targets (EC2, IP, Lambda). Health checks are configured at the target group level.

### 5. What are Health Checks?
**Answer:**
Health checks monitor target instances to ensure traffic is only routed to healthy instances. If an instance fails health checks, it is automatically removed from routing until it becomes healthy again.

### 6. What is Cross-Zone Load Balancing?
**Answer:**
Cross-zone load balancing distributes traffic evenly across instances in **all enabled Availability Zones**, regardless of how many instances are in each zone. This prevents traffic imbalance if one AZ has fewer instances than another.

## 🔹 Intermediate Level

### 7. Explain how ALB performs routing.
**Answer:**
ALB supports advanced routing rules based on:
*   **Host-based routing:** (e.g., `api.example.com` vs `www.example.com`).
*   **Path-based routing:** (e.g., `/images`, `/app`).
*   **HTTP header-based routing.**
*   **Query string routing.**
*   **Source IP routing.**

It uses **Listener Rules** to evaluate these conditions and forward traffic to the appropriate Target Group.

### 8. What is SSL Termination?
**Answer:**
**SSL Termination** decrypts HTTPS traffic at the load balancer level, reducing the processing burden (CPU overhead) on backend servers.
*   Certificates are managed via **AWS Certificate Manager (ACM)**.

### 9. What is Sticky Session (Session Affinity)?
**Answer:**
Sticky sessions bind a user's session to a specific target using cookies, ensuring the user consistently connects to the same backend server for the duration of the session.
*   **ALB:** Uses application-based cookies or duration-based cookies generated by the LB.
*   **CLB:** Uses duration-based cookies.

### 10. What are Listeners?
**Answer:**
A **Listener** is a process that checks for connection requests using a specific protocol and port (e.g., HTTPS:443) and forwards requests to target groups based on configured rules.

### 11. How does Load Balancer integrate with Auto Scaling?
**Answer:**
When used with **Amazon EC2 Auto Scaling**:
1.  New instances launched by Auto Scaling are automatically registered to the Target Group.
2.  Terminated instances are automatically deregistered.
3.  **Health Checks:** If an LB health check fails, Auto Scaling terminates the unhealthy instance and launches a replacement.

### 12. What is Deregistration Delay?
**Answer:**
It is the time the load balancer waits before removing a target from service (formerly called **Connection Draining**). It allows in-flight requests to complete before the connection is closed.

## 🔹 Advanced Level

### 13. Explain how NLB handles high performance workloads.
**Answer:**
*   Operates at **Layer 4** (Transport Layer).
*   Handles **millions of requests per second**.
*   **Preserves Source IP** of the client.
*   Uses **Static IPs** or Elastic IPs per Availability Zone.
*   Designed for extreme low latency.

### 14. What is Gateway Load Balancer (GWLB)?
**Answer:**
**Gateway Load Balancer** is used to deploy, scale, and manage third-party virtual appliances (firewalls, intrusion detection systems, deep packet inspection).
*   **Combines:** Layer 3 Gateway + Layer 4 Load Balancing.
*   **Mechanism:** Uses **GENEVE** protocol to encapsulate traffic transparently.

### 15. How does ALB support microservices architecture?
**Answer:**
*   **Container Support:** Integrates natively with ECS and EKS.
*   **Routing:** Path-based and Host-based routing allow serving multiple microservices (e.g., `/orders`, `/users`) behind a single Load Balancer.
*   **Dynamic Port Mapping:** Allows multiple containers of the same service to run on the same host on random ports.

### 16. How can you secure an AWS Load Balancer?
**Answer:**
*   **Security Groups:** Restrict inbound access to specific IPs.
*   **HTTPS/TLS:** Enable HTTPS listeners with ACM certificates.
*   **WAF:** Attach **AWS WAF** to the ALB to block malicious traffic (SQLi, XSS).
*   **Backend Security:** Restrict backend EC2 Security Groups to allow traffic *only* from the Load Balancer's Security Group.
*   **Access Logs:** Enable logs for auditing.

### 17. What are Load Balancer Algorithms in AWS?
**Answer:**
*   **ALB:** Round Robin (default), Least Outstanding Requests.
*   **NLB:** Flow Hash Algorithm (based on protocol, source IP, source port, destination IP, destination port).
*   **CLB:** Round Robin (TCP), Least Outstanding Requests (HTTP).

### 18. How does ALB handle WebSockets?
**Answer:**
ALB supports **WebSockets** natively over HTTP/HTTPS. It maintains long-lived TCP connections between the client and the target.

### 19. What are the differences between ELB and Route 53?
**Answer:**

| Feature | ELB (Elastic Load Balancing) | Route 53 |
| :--- | :--- | :--- |
| **Function** | Distributes traffic across instances/targets. | DNS-based routing (Domain Name System). |
| **Level** | Works at Request level (Regional). | Works at DNS resolution level (Global). |
| **Health Checks** | Checks instances/targets. | Checks endpoints/resources globally. |

### 20. What is Connection Draining?
**Answer:**
**Connection Draining** (now referred to as **Deregistration Delay** in ALB/NLB) ensures that when an instance is deregistering or unhealthy, the load balancer stops sending new requests but allows existing in-flight requests to complete within a specified timeout.

### 21. Explain how to troubleshoot 502/503 errors in ALB.
**Answer:**
*   **502 Bad Gateway:** The load balancer received an invalid response from the target.
    *   *Causes:* Application crash, connection reset by peer, header size too large.
*   **503 Service Unavailable:** The load balancer has no healthy targets.
    *   *Causes:* Target groups empty, health checks failing, security groups blocking traffic.
*   **General Checks:** Security groups, target health, application logs, timeout mismatches.

### 22. Can you use Lambda with ALB?
**Answer:**
**Yes.** ALB supports Lambda functions as targets. This allows you to build serverless HTTP endpoints using ALB routing features without needing API Gateway.

### 23. What metrics are important in CloudWatch for ELB?
**Answer:**
*   `RequestCount`
*   `HealthyHostCount` / `UnHealthyHostCount`
*   `TargetResponseTime` (Latency)
*   `HTTPCode_ELB_5XX` (LB errors)
*   `HTTPCode_Target_5XX` (App errors)
*   `SurgeQueueLength` (CLB/Classic)

### 24. Explain Multi-Tier Architecture using ALB & NLB.
**Answer:**
*   **Public ALB:** Handles internet-facing HTTP/HTTPS traffic, WAF protection, and routing to web servers.
*   **Internal ALB:** Handles service-to-service communication within the VPC.
*   **NLB:** Handles TCP traffic for databases or high-performance internal services.

### 25. Scenario: Your application receives unpredictable traffic spikes. How would you design a highly available architecture using ALB?
**Answer:**
1.  **Multi-AZ:** Deploy instances across multiple Availability Zones.
2.  **Cross-Zone LB:** Enable Cross-Zone Load Balancing on the ALB.
3.  **Auto Scaling:** Attach an Auto Scaling Group (ASG) to the Target Group with dynamic scaling policies (CPU/Request Count).
4.  **Health Checks:** Configure aggressive health checks to remove failing nodes quickly.
5.  **Caching:** Use Redis/ElastiCache for session storage (stateless app).
6.  **Protection:** Enable WAF and Shield.

## 🔹 Expert / Architect-Level Questions

### 26. How does ALB support HTTP/2 and gRPC?
**Answer:**
ALB supports **HTTP/2** natively on the client side (listener) and converts it to HTTP/1.1 for targets. It also supports **gRPC** workloads by using HTTP/2 on both the listener and the target (requires gRPC specific health checks).

### 27. How does Load Balancer pricing work?
**Answer:**
Charges are based on:
1.  **Hourly Charge:** Per Load Balancer-hour (or partial hour).
2.  **Capacity Units (LCU):** Based on usage dimensions:
    *   New connections.
    *   Active connections.
    *   Processed bytes.
    *   Rule evaluations (for ALB).

### 28. When would you choose NLB over ALB?
**Answer:**
Choose **NLB** when you need:
*   **Static IP / Elastic IP** addresses for the load balancer.
*   **Ultra-low latency** (TCP/UDP).
*   **High throughput** (millions of requests/sec).
*   **Source IP preservation** (without X-Forwarded-For headers).
*   Non-HTTP protocols.

### 29. How to implement Blue-Green deployment with ALB?
**Answer:**
1.  Create two Target Groups: **Blue** (Current) and **Green** (New).
2.  Deploy the new version to the Green Target Group.
3.  **Switch Traffic:** Update the ALB Listener Rule to forward traffic from Blue to Green.
4.  **Weighted Routing:** Alternatively, use listener weights to shift traffic gradually (e.g., 10% to Green, 90% to Blue) for Canary testing.

### 30. What are common real-world design patterns?
**Answer:**
*   **Internet-facing ALB → Internal ALB:** Web tier talks to App tier via internal LB.
*   **ALB + WAF + Auto Scaling:** Standard secure web application pattern.
*   **NLB + PrivateLink:** Exposing services privately to other VPCs.
*   **Multi-region:** Route 53 (DNS LB) → Regional ALBs.
